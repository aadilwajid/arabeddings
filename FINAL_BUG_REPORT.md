## 🔴 BUG #2: Invalid Password Hashes (CRITICAL)

### Severity: CRITICAL
### Status: ⚠️ NEEDS FIX
### Impact: Admin login broken

### Problem
The `data/users.json` file contains placeholder password hashes that don't match any real passwords.

### Current State
```json
{
  "email": "admin@arabeddings.com",
  "password": "$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"
}
```

These are **fake hashes** that won't authenticate.

### Root Cause
The users.json file was manually created with placeholder strings instead of being generated by the seed script using `bcrypt.hashSync()`.

### Solution Required
Run the seed script to generate proper bcrypt hashes:

```bash
npm run seed
```

This will:
1. Generate real bcrypt hashes for all users
2. Create proper UUIDs for user IDs
3. Set correct timestamps

### Expected Credentials After Fix
```
Admin:
  Email: admin@arabeddings.com
  Password: password

Manager:
  Email: manager@arabeddings.com
  Password: manager123

Support:
  Email: support@arabeddings.com
  Password: support123
```

### How to Verify
After running seed script:
```bash
# Test admin login
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@arabeddings.com","password":"password"}'

# Should return: {"success":true,"user":{...}}
```

## 🟡 BUG #3: Missing Environment Variables (MEDIUM)

### Severity: MEDIUM
### Status: ⚠️ NEEDS ATTENTION
### Impact: JWT tokens use hardcoded secret

### Problem
The JWT secret is hardcoded in the auth API:

```typescript
// src/app/api/auth/login/route.ts
const JWT_SECRET = process.env.JWT_SECRET || 'ara-beddings-secret-key-2026';
```

### Risk
- Security vulnerability in production
- Secret exposed in source code
- All deployments use same secret

### Solution Required
Create `.env.local` file:

```env
JWT_SECRET=your-super-secret-key-here-change-in-production
NODE_ENV=development
```

### Production Setup
For Vercel deployment:
1. Go to Project Settings → Environment Variables
2. Add `JWT_SECRET` with a strong random value
3. Redeploy

### Generate Strong Secret
```bash
# Generate a random 64-character string
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
